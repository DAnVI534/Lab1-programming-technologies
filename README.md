# Лабораторная работа 1. Сбор параметров операционной системы

## Что делает скрипт

Скрипт `sysinfo_collector.py` определяет, в какой операционной системе он запущен (Linux, macOS или Windows), собирает параметры этой системы и сохраняет их в файл формата JSON.

**Запуск:** Требуется Python 3.10+.

**Ход работы скрипта:**

1. Тип ОС определяется через `platform.system()`: возвращается `Linux`, `Darwin` (macOS) или `Windows`.
2. Каждая группа параметров собирается отдельной функцией, в зависимости от OC своей строчкой кода.
3. Если какой-то раздел (`python`, `host`, `cpu`, `memory`, `disk`, `network`) не удалось собрать, вместо всего раздела записывается `null`, а скрипт продолжает работу. Параметры, которых нет на данной ОС (например, `mac_version` на Linux), в JSON просто не добавляются.
4. Результат записывается в JSON-файл `system_info.json`.

## Собираемые параметры и чем они собираются

Параметры сгруппированы по разделам JSON. Для каждого указано, какой стандартный инструмент Python его получает.

**`collected_at`: собирает дату и время сбора данных в формате ISO 8601 с указанием часового пояса** `2026-10-01T02:52:00+03:00`
- с помощью `datetime.now().astimezone()`

**`os`: собирает данные о операционной системе** (функция сбора: `get_os()`)
- `system`: название ОС (`Linux`, `Darwin`, `Windows`), получено через `platform.system()`
- `release`: версия выпуска / ядра, получена через `platform.release()`
- `version`: подробная версия или сборка, получена через `platform.version()`
- `machine`: архитектура процессора, получена через `platform.machine()`
- `distro`: название дистрибутива (только Linux), получено через `platform.freedesktop_os_release()`
- `mac_version`: версия macOS (только macOS), получена через `platform.mac_ver()`
- `windows_build`: номер сборки Windows, получен через `platform.win32_ver()`
- `windows_edition`: редакция Windows, например Home или Pro, получена через `platform.win32_edition()`

**`python`: данные о версии интерпретатора и путь к исполняемому файлу**
- `version`: версия Python, получена с помощью `platform.python_version()`
- `executable`: путь к исполняемому файлу Python, получен с помощью `sys.executable`

**`host`: данные о компьютере и пользователе**
- `hostname`: имя компьютера, получено через `socket.gethostname()`
- `user`: текущий пользователь, получен через `getpass.getuser()`
- `home_dir`: домашний каталог, получен через `os.path.expanduser("~")`
- `timezone`: название часового пояса, получено через `datetime.now().astimezone().tzname()`
- `utc_offset_hours`: смещение от UTC в часах (с учётом летнего времени), получено через `utcoffset()`
- `is_admin`: запущен ли скрипт с правами администратора / root; на Linux и macOS через `os.geteuid()`, на Windows через `ctypes.windll.shell32.IsUserAnAdmin()`

**`cpu`: данные о процессоре**
- `logical_cores`: число логических ядер, получено через `os.cpu_count()`
- `model`: модель процессора (только Windows), взята из переменной окружения `PROCESSOR_IDENTIFIER` (через `os.environ`)
- `load_average`: средняя загрузка за 1, 5 и 15 минут (Linux, macOS), получена через `os.getloadavg()`

**`memory`: информация об оперативной памяти**
- `total_gb`: кол. общей памяти, ГБ; на Linux и macOS через `os.sysconf("SC_PAGE_SIZE")` и `os.sysconf("SC_PHYS_PAGES")`, на Windows через системный вызов `GlobalMemoryStatusEx` (`ctypes`)
- `available_gb`: кол. доступной памяти, ГБ (Linux, Windows); на Linux через `os.sysconf("SC_AVPHYS_PAGES")`, на Windows через `GlobalMemoryStatusEx`
- `used_percent`: процент использования (Linux, Windows), вычислен из общего и доступного объёма

**`disk`: информация о системном диске (`/` или `C:\`)**
- `root`: путь к проверяемому диску, выбирается по типу ОС
- `total_gb`, `used_gb`, `free_gb`: размер, занято и свободно в ГБ, получено с помощью `shutil.disk_usage()`
- `used_percent`: процент заполнения, вычислен из занятого и общего объёма

**`network`: данные о сети**
- `hostname`: имя компьютера, получено через `socket.gethostname()`
- `ip_addresses`: IP-адреса компьютера, получено через `socket.gethostbyname_ex()`

## Используемые библиотеки и что они достают

- **`platform`**: название ОС, название дистрибутива Linux, версия выпуска, подробная версия, архитектура процессора, версия macOS, сборка и редакция Windows, версия Python
- **`os`**: число логических ядер, средняя загрузка, права root, домашний каталог, объём памяти на Linux и macOS (`sysconf`), переменная окружения с моделью процессора на Windows
- **`sys`**: путь к интерпретатору Python и аргумент командной строки с именем выходного файла
- **`socket`**: имя компьютера и его IP-адреса
- **`shutil`**: размер, занятое и свободное место на системном диске
- **`getpass`**: имя текущего пользователя
- **`ctypes`**: вызовы WinAPI на Windows: проверка прав администратора (`IsUserAnAdmin`) и объём памяти (`GlobalMemoryStatusEx`)
- **`datetime`**: время сбора данных в местном времени с часовым поясом, название часового пояса и смещение от UTC
- **`json`**: запись собранных данных в файл `.json`

## Почему выбрано именно так

**Набор параметров.** Выбраны характеристики, которые отвечают на базовые вопросы о машине: что за система (`os`, `python`), чья она и как называется (`host`), какие у неё ресурсы (`cpu`, `memory`, `disk`) и как она видна в сети (`network`). Параметры вроде версии ядра, лимитов и сотен переменных окружения не брались: они мало что добавляют, а часть может содержать личные данные. Так сохранён баланс между количеством и качеством.

**Значение `null` вместо ошибки.** Разные ОС отдают разный набор данных (например, на Windows нет load average). Если сбор раздела завершился ошибкой, скрипт не падает, а записывает вместо раздела `null`, чтобы он работал на всех трёх системах. Раздел `os` собирается без такой защиты, потому что без типа ОС остальные разделы собрать нельзя.
